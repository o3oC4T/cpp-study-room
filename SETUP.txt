실제 서비스 상태
- Supabase 서울 리전의 무료 프로젝트에 초기 DB와 classroom 함수를 배포했다.
- 원격 Auth 정책을 적용하고 roomowner, friend01~friend05를 실제 발급했다.
- 6개 계정 로그인, 공개 가입 거부, 현재 비밀번호 검증/변경, 운영자 발급,
  학생의 권한 상승/다른 회원 기록 접근 거부, 비활성 계정 거부를 실제 서버에서 검증했다.
- 검증용 임시 계정/기록은 삭제했고 발급한 6개 계정만 남아 있다.
- 원격 채점은 GitHub App 연결과 실제 Windows 작업 검증 전까지 비활성화한다.
- Supabase 무료 플랜은 유출 비밀번호 목록 대조를 지원하지 않는다.
  https://supabase.com/docs/guides/auth/password-security#password-strength-and-leaked-password-protection

신규 서버 설정 순서
1. Supabase 연결을 승인하고 대상 프로젝트를 선택한다.
   웹사이트 로그인 상태는 작업 도구의 연결과 다르다.
2. supabase/migrations의 SQL과 classroom 함수를 배포한다.
   현재 서버에는 이미 초기 SQL을 적용했다. 같은 초기 SQL을 다시 실행하지 않는다.
   기존 GitHub OAuth 회원 스키마를 이미 사용 중인 별도 서버에 덮어쓰면 안 된다.
3. 원격 Auth 설정에서 새 회원가입을 비활성화한다(disable_signup=true).
   이메일·비밀번호 로그인만 사용하며 OAuth/익명 로그인/공개 회원가입을 사용하지 않는다.
   비밀번호 최소 길이 12, JWT 수명 900초를 설정하고 Auth 로그인 rate limit을 유지한다.
   supabase/config.toml의 로컬 설정만으로 호스팅된 프로젝트 설정이 바뀌지는 않는다.
   초기 설정용 scripts/configure-supabase.mjs는 프로세스 환경의
   SUPABASE_ACCESS_TOKEN / SUPABASE_PROJECT_REF를 받아 원격 정책 적용·재조회,
   함수 환경 설정, 계정 발급을 수행한다. 채점은 비활성화하므로 초기 설치 때만 실행한다.
4. 신뢰할 수 있는 터미널에서 서버 전용 SUPABASE_URL, SUPABASE_SERVICE_ROLE_KEY를
   프로세스 환경으로 전달한 뒤 node scripts/provision-accounts.mjs를 실행한다.
   roomowner 1개와 friend01~friend05 5개를 생성한다. 재실행 시 기존 비밀번호는 바꾸지 않는다.
   무작위 초기 비밀번호는 .local/credentials 아래 전달용 파일에만 쓴다.
   파일은 공개 git·빌드·Vite 서빙에서 제외된다. 안전하게 전달한 뒤 삭제한다.
5. 사용자 비밀번호는 Supabase Auth가 salt를 포함한 bcrypt 해시로 보관한다.
   사이트 코드, members 테이블, 브라우저 저장소에 평문이나 비교용 해시를 넣지 않는다.
   초기 비밀번호는 발급 직후 전달을 위해 한 번 제공한다. 첫 변경 이후 초기값은 무효다.
   해시 방식도 약한 비밀번호의 추측 공격을 절대 불가능하게 만들지는 않는다.
   새 비밀번호는 12자 이상, UTF-8 72바이트 이하이며 서버에서 현재 비밀번호를 재검증한다.
6. 초기 비밀번호 변경 전에는 제출·추가 계정 발급을 허용하지 않는다.
   운영자는 내 계정에서 친구 계정을 추가 발급할 수 있다. 역할은 DB에서만 읽는다.
   클라이언트는 members/submissions 쓰기 권한이 없으며 자신의 활성 계정 기록만 읽는다.
   비밀번호 변경 뒤 refresh token을 전체 로그아웃한다. 이미 발급된 access JWT는
   최대 15분의 유효기간 동안 남을 수 있으므로 완전한 즉시 무효화로 표현하지 않는다.
7. 비공개 과제 저장소 하나에 설치한 GitHub App을 연결한다.
   Repository permissions: Contents read/write, Actions read, Metadata read.
   개인 gh 로그인 토큰을 서비스 키로 복사하지 않는다. App private key는 PKCS#8으로
   변환해 Supabase secret에만 저장한다. .env.example에는 값이 없는 항목만 둔다.
8. GitHub Pages repo variables에 SUPABASE_URL / SUPABASE_PUBLISHABLE_KEY를 설정한다.
   서비스 키, 비밀번호, GitHub App private key는 Vite 변수에 넣지 않는다.
9. 실제 서버에서 다음을 확인한 뒤에만 서버 JUDGE_ENABLED와 Pages 변수 JUDGE_ENABLED를 true로 설정한다.
   - 발급 계정 로그인/비밀번호 변경, 무단 회원가입 거부, 비회원·다른 회원 기록 접근 거부
   - 학생의 운영자 기능 호출 거부, 비활성 계정 거부, 원문 비밀번호 비저장
   - 제출 커밋 → 해당 커밋의 Windows 채점 → 결과 artifact 검증 → 회원 기록 저장
   로컬 테스트 및 모의 API 브라우저 테스트는 이 검증을 대신하지 않는다.
   실제 인증 검증: 서버 전용 SUPABASE_URL / SUPABASE_SERVICE_ROLE_KEY와
   SUPABASE_PUBLISHABLE_KEY를 프로세스 환경으로 전달하고
   node scripts/verify-hosted-auth.mjs .local/credentials/initial-accounts-<발급시각>.txt
   검증은 초기 비밀번호를 아직 바꾸지 않은 신규 발급 직후에 수행한다.
   별도 임시 계정으로 변경/권한 검증을 수행하고 직접 만든 임시 데이터만 제거한다.

데이터 작성
- .local/course/authoring/practice.mjs에 신규 문제의 정답·독립 출력 계산기·입력 생성기가 있다.
  node .local/course/authoring/practice.mjs --build .
  공개 src/practice.json에는 지문·기본 코드·예제만 추출한다.
- private reference/*.cpp는 BOM+CRLF로 저장한다. 공개 사이트로 복사하지 않는다.
- 신규 ID는 practice-1-1 ~ practice-8-4. 기존 midterm-1~4는 보존한다.
- backend validation, DB constraint, judge manifest validation 모두 같은 범위만 허용한다.
- 공개 judge/{Sandbox.cs,common.ps1,grade.ps1}은 private judge/와 일치시킨다.
- 교수님 PDF, 과제 정답, 비공개 입력, 자격 증명을 공개 저장소에 넣지 않는다.

채점
- Windows MSVC /EHsc /W3 /Od /MDd /permissive- /utf-8
- 실행: 벽시계 2초 / 메모리 256MB / stdout+stderr 64KB / 프로세스 1개.
- 컴파일: 45초 / 1GB. 모든 컴파일과 실행은 Windows AppContainer 내부에서 수행한다.
- CRLF/LF만 정규화. 공백·빈 줄·마지막 줄바꿈·숫자 정밀도는 그대로 비교한다.
- 함수 사용/범위 준수/메모리 해제는 출력 테스트만으로 완전히 검증되지 않는다.
- 정답, 오답, CE, RE, TLE, MLE, 출력 초과, 시스템 오류를 구분한다.
- 반례 찾기: 경계값 + 시드가 고정된 무작위 입력 16개, 첫 실패의 입력·기대·실제 출력 표시.
  최소 반례를 보장하지 않으며 반례 없음은 정답 통과로 집계하지 않는다.
- 예제/전체/반례 모두 최근 24시간 1인 5회, 전체 20회 한도를 공유한다.
- 최근 제출 100개와 별개로 전체 통과 문제를 집계한다.

격리
- capability 없는 AppContainer, Job Object 할당 후 프로세스 시작, 전체 작업 트리 종료.
- child env/상속 핸들 허용 목록. 설치된 MSVC ACL은 바꾸지 않고 임시 도구만 복사한다.
- 런타임은 디버그 런타임 폴더만 읽는다. reparse point를 따라가며 정리하지 않는다.
- Supabase/GitHub App 키는 채점 job과 학생 코드에 전달하지 않는다.
- 결과 zip은 메모리에서 제한된 result.json만 읽고 실행/디스크 압축 해제하지 않는다.
- 결과는 제출 UUID·문제·모드·정확한 커밋 및 workflow run을 확인한다.
